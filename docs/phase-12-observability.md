# Фаза 12 — Observability baseline

## Реалізовано

- Сторінка `/health` перевіряє frontend і доступність бази через обмежену публічну RPC.
- Автоматично фіксуються переходи між сторінками, час первинного завантаження, route errors, `window.error` та необроблені Promise-помилки.
- Аналітика вимкнена за замовчуванням і вмикається користувачем у налаштуваннях приватності.
- `Do Not Track` вимикає клієнтський збір навіть за збереженої згоди.
- URL query, email, пошукові запити, stack trace і відеодані не записуються.
- База приймає лише allow-list подій, шлях до 300 символів і JSON до 4 KB.
- Прямий запис у `app_events` заборонено; запис виконує RPC, яка повторно перевіряє згоду.
- Перегляд подій через RLS доступний лише редакторам каталогу.

## Потрібна дія в Supabase

Застосувати `20260806300000_observability.sql` у SQL Editor. Після цього:

1. Відкрити `/settings/privacy` і за бажанням увімкнути приватну аналітику.
2. Відкрити кілька сторінок.
3. Перевірити `/health`: має з’явитися повідомлення «Усі системи працюють».
4. Для перевірки даних під роллю editor виконати `select * from public.app_events order by created_at desc limit 20;`.

Для production ще потрібен зовнішній uptime-monitor, який опитуватиме `/health` за розкладом.
